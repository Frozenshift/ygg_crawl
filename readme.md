# Обход нод Yggdrasil

`ygg_crawl.js` обнаруживает публичные ключи нод Yggdrasil через локальный экземпляр сети, вычисляет их IPv6-адреса и проверяет ответы на удалённые debug-запросы. Список сохраняется в JSON и TXT. `parse-result.js` создаёт из JSON отчёт на русском языке: сколько нод найдено, активно, не ответило и осталось непроверенным.

## Проверка задержки: ping.js

```powershell
node .\ping.js
```

Создаёт `ping.md` по активным удалённым нодам (`responded`) из `ygg-nodes-js.json`. Локальная нода исключается, повторные IPv6 удаляются. Для текущего снимка это 7 580 адресов. Нужны работающий Yggdrasil с IPv6-маршрутом, Node.js и системный `ping`; поддерживаются Windows и Linux, npm-пакеты не требуются.

В отчёте: средняя, минимальная и максимальная задержка в миллисекундах, количество ответов и потери. Сортировка числовая по средней задержке полученных ответов от меньшей к большей; при равенстве — по адресу. Потери не влияют на порядок. Ноды без ответа стоят в конце с прочерком вместо времени.

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--input FILE` | `ygg-nodes-js.json` | JSON со статусами нод |
| `--output FILE` | `ping.md` | Markdown-отчёт; существующий файл заменяется |
| `--workers N` | `32` | Одновременные проверки нод; целое > 0 |
| `--count N` | `3` | ICMP-запросов на ноду; целое > 0 |
| `--timeout S` | `2` | Тайм-аут ответа в секундах, > 0 и ≤ 3600; Linux округляет вверх до целой секунды |
| `--limit N` | `0` | Первые N активных адресов в порядке JSON; 0 — все |
| `--help`, `-h` | — | Справка |

Пробный запуск на первых 10 адресах:

```powershell
node .\ping.js --limit 10 --count 1 --timeout 1 --output .\ping-sample.md
```

Проверка всех активных адресов с пятью запросами:

```powershell
node .\ping.js --workers 32 --count 5 --timeout 3
```

Отчёт сохраняется перед началом опроса, примерно каждые 5 секунд и после завершения. `Ctrl+C` прекращает новые проверки, ждёт текущие процессы и сохраняет частичный отчёт. В нём указаны состояние запуска, число выбранных и проверенных адресов и остаток. Продолжение не поддерживается: новый запуск измеряет всё заново. Код выхода: `0` — завершение, `1` — общая ошибка, `130` — обработанная остановка.

Windows округляет время до целых миллисекунд. Ответ `<1 мс` учитывается как верхняя граница 1 мс; статистика такой ноды помечается `≤`. Среднее считается только по полученным ответам, поэтому рядом следует учитывать потери. При ошибке процесса доля неполученных ответов может включать неотправленные запросы.

Это измерение задержки от вашего компьютера, а не пропускной способности в Мбит/с. Старый статус `responded` не гарантирует ответ на ICMP сейчас. Неответившие ноды могут фильтровать ICMP или иметь проблемы маршрута. Высокий параллелизм может влиять на результаты из-за нагрузки.

Проверки парсинга, сортировки, очереди и системного IPv6 ping:

```powershell
node --test .\ping.test.js
```

## Требования

- Node.js 18 или новее. Оба скрипта используют встроенные модули; `npm install` не нужен.
- Для обхода — работающий локальный демон Yggdrasil с подключениями к сети и утилита `yggdrasilctl` в `PATH` либо её путь через `--ctl`. На Windows по умолчанию вызывается `yggdrasilctl.exe`.
- Доступ к локальному admin endpoint демона. Если Windows запрещает доступ, запустите PowerShell от имени администратора.
- Для генерации отчёта нужны только Node.js и сохранённый JSON; работающий Yggdrasil не требуется.

Команды ниже выполняются из каталога проекта.

## Быстрый запуск

```powershell
node .\ygg_crawl.js --workers 200 --timeout 10 --interval 0.01
node .\parse-result.js
```

Первая команда — параметры, использованные для текущего результата. Вторая создаёт или перезаписывает `result.md` по `ygg-nodes-js.json`.

Чтобы включить в отчёт команду обхода:

```powershell
node .\parse-result.js --command 'node .\ygg_crawl.js --workers 200 --timeout 10 --interval 0.01'
```

JSON не хранит параметры обхода. `--command` добавляет переданный текст в отчёт и не выполняет его.

## Как работает обход

1. Через `getself` получает ключ локальной ноды, через `getpeers` и `gettree` — начальные ключи.
2. Для каждой новой удалённой ноды последовательно выполняет `debug_remotegetpeers` и `debug_remotegettree`.
3. Рекурсивно извлекает из ответов ненулевые 64-значные шестнадцатеричные ключи, включая имена полей, убирает повторы и ставит новые ключи в очередь.
4. Вычисляет Yggdrasil IPv6 по публичному ключу; хранит статусы, успешные команды и ошибки.
5. Примерно раз в 5 секунд сохраняет снимок и выводит прогресс. После завершения сохраняет итог ещё раз.

Применяется локальный `yggdrasilctl`, удалённый административный порт открывать не нужно. Скрипт не выполняет ping, сканирование портов или проверку сервисов на найденных адресах. Параллелизм реализован асинхронными проверками и дочерними процессами `yggdrasilctl`, а не потоками CPU.

## Параметры ygg_crawl.js

Все значения времени задаются в **секундах**. Параметры передаются отдельными аргументами: `--timeout 10`.

| Параметр | По умолчанию | Назначение и ограничения |
| --- | --- | --- |
| `--workers N` | `16` | Максимум одновременно проверяемых нод. Положительное безопасное целое. |
| `--timeout S` | `10` | Тайм-аут каждого отдельного вызова `yggdrasilctl`, включая начальные команды. Положительное конечное число. |
| `--interval S` | `0.01` | Минимальная общая пауза между стартами проверок нод. Конечное число ≥ 0; `0` отключает паузу. |
| `--max-nodes N` | `1000000` | Предел числа записанных уникальных ключей, включая локальный. Безопасное целое ≥ 2. |
| `--max-seconds S` | `86400` | Максимальное время запуска, включая начальные запросы. Положительное конечное число. |
| `--output PREFIX` | `ygg-nodes-js` | Префикс файлов: `PREFIX.json` и `PREFIX.txt`; каталоги создаются автоматически. |
| `--ctl PATH` | `yggdrasilctl.exe` на Windows, `yggdrasilctl` в остальных ОС | Путь к локальной утилите. Пути с пробелами заключайте в кавычки. |
| `--endpoint URI` | Не задан | Передаёт `-endpoint URI` утилите для выбора локального admin endpoint. |
| `--resume FILE` | Не задан | Продолжает ранее сохранённый Python/JS JSON-снимок с массивом `nodes` и совместимыми полями записей. |
| `--help`, `-h` | — | Выводит справку и завершает работу. |

**Особенность текущей справки:** `--help` пишет про диапазон `--workers 1–64`, однако код не проверяет верхний предел 64 и принимает `200`. Команда выше допускает до 200 параллельных проверок. Увеличение значения повышает нагрузку на локальный демон и число дочерних процессов.

Два запроса к одной ноде выполняются последовательно: при `--timeout 10` её проверка может занять примерно 20 секунд плюс накладные расходы. `--interval 0.01` ограничивает старты проверок примерно сотней в секунду, но не гарантирует такую скорость. Это не интервал между каждым отдельным debug-запросом. Тайм-аут команды сокращается, если до общего дедлайна осталось меньше времени.

## Примеры обхода

Обычный запуск с параметрами по умолчанию:

```powershell
node .\ygg_crawl.js
```

Обход на 10 минут с лимитом 5 000 ключей и отдельным каталогом результатов:

```powershell
node .\ygg_crawl.js --workers 16 --max-seconds 600 --max-nodes 5000 --output .\results\scan
```

Путь к утилите и явный локальный endpoint (URI должен соответствовать настройкам вашего демона):

```powershell
node .\ygg_crawl.js --ctl 'C:\Program Files\Yggdrasil\yggdrasilctl.exe' --endpoint 'tcp://localhost:9001'
```

Продолжение снимка с сохранением в новые файлы:

```powershell
node .\ygg_crawl.js --resume .\ygg-nodes-js.json --output .\results\continued
```

При продолжении завершённые записи `responded` и `unresponsive` пропускаются. Если `inspection_complete` явно равен `false`, запись проверяется повторно; у старых снимков без этого поля завершённость определяется статусом. Локальная нода определяется заново. `--max-nodes` должен быть строго больше количества загруженных ключей.

`--resume` продолжает обнаружение, сохраняя старые результаты, и не проверяет заново доступность всех нод. Для свежего опроса запустите обход без `--resume`. Поле `elapsed_seconds` относится к текущему запуску, а `queried` при продолжении включает уже завершённые проверки из снимка.

## Статусы и смысл активности

| Статус | Значение | Учёт в отчёте |
| --- | --- | --- |
| `local` | Локальная нода, определённая через `getself` | Активная |
| `responded` | Хотя бы одна debug-команда завершилась успешно; вторая могла вернуть ошибку | Активная |
| `unresponsive` | Проверка завершена, ни одна debug-команда не завершилась успешно | Неактивная по результатам опроса |
| `discovered` | Ключ найден, но проверка не выполнена или не завершена без успешного ответа | Отдельная категория, доступность не установлена |

Неполная проверка с хотя бы одним успешным ответом получает `responded` и `inspection_complete: false`; при продолжении она будет повторена. Неизвестные и отсутствующие статусы парсер выводит отдельной категорией.

Неответившая нода не обязательно выключена: возможны ошибки маршрутизации, тайм-ауты и недоступность debug-команд. Найденный ключ также не доказывает существование отдельного физического устройства. Результат отражает доступную через этот обход часть сети; полного перечня всех нод он не гарантирует.

## Файлы результатов

`ygg-nodes-js.json` содержит метаданные и массив `nodes`, отсортированный по публичному ключу.

| Поле JSON | Содержание |
| --- | --- |
| `queried` | Число завершённых проверок удалённых нод |
| `elapsed_seconds` | Длительность текущего запуска |
| `reason` | Состояние или причина завершения |
| `updated_utc` | Время последнего сохранения в UTC |
| `discovered` | Общее число записей, включая локальную |
| `responded` | Число записей со статусом `local` или `responded` |
| `note` | Примечание об ограничениях обнаружения |
| `resumed_from`, `resumed_at` | Путь исходного снимка и время продолжения, если использован `--resume` |
| `error` | Описание общей ошибки, если она возникла |
| `nodes[].public_key`, `nodes[].ipv6` | Публичный ключ и вычисленный IPv6 |
| `nodes[].status` | Статус записи |
| `nodes[].successful_requests` | Имена успешно выполненных debug-команд |
| `nodes[].errors` | Ошибки по именам команд |
| `nodes[].inspection_complete` | Выполнены обе попытки запроса; у локальной записи поле может отсутствовать |

`ygg-nodes-js.txt` содержит **все** найденные IPv6, по одному на строку, включая неответившие и непроверенные ноды. Это не список только активных адресов.

При сохранении JSON и TXT сначала записываются во временные файлы с суффиксом `.tmp`, затем переименовываются. Существующие результаты с тем же префиксом заменяются; два файла обновляются по отдельности.

## Прогресс, остановка и ошибки

В консоли выводятся `Discovered` (число найденных ключей), `queried` (завершённые проверки), `queued` (очередь) и `active` (текущие проверки). **`active` в консоли — число выполняющихся задач, а не число активных нод в отчёте.**

`Ctrl+C` прекращает запуск новых задач, ожидает текущие команды и сохраняет результат. Скрипт также обрабатывает `SIGTERM`. При принудительном завершении процесса останется последний успешно записанный снимок.

Возможные значения `reason`:

- `running` — промежуточный снимок выполняющегося обхода.
- `no_more_discoveries` — очередь исчерпана; новых ключей нет. Это не гарантия полного обхода сети.
- `time_limit` — достигнут предел времени.
- `node_limit` — часть новых ключей не записана из-за лимита; уже записанные ноды продолжают обрабатываться в пределах времени.
- `interrupted` — получен сигнал остановки.
- `error` — общая ошибка, например недоступность локального admin endpoint.

Ошибки отдельных удалённых запросов сохраняются в записи ноды и не останавливают весь обход. Общие ошибки выводятся в консоль; при наличии записей скрипт пытается сохранить их. Код выхода обхода: `0` — штатное завершение, включая лимиты; `1` — ошибка; `130` — обработанное прерывание без общей ошибки.

## Генератор отчёта parse-result.js

```powershell
node .\parse-result.js --input .\results\scan.json --output .\reports\scan.md
node .\parse-result.js --help
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--input FILE` | `ygg-nodes-js.json` | JSON-снимок для анализа |
| `--output FILE` | `result.md` | Markdown-файл отчёта; существующий перезаписывается, каталоги создаются |
| `--command TEXT` | Не задан | Текст команды обхода для включения в отчёт |
| `--help`, `-h` | — | Справка |

Парсер считает записи по массиву `nodes`, а не доверяет итоговым счётчикам в заголовке. Проверяет формат публичных ключей и отсутствие повторов без учёта регистра. При некорректном JSON, неверных ключах, повторных ключах или ошибке чтения/записи выводит сообщение и завершает работу с кодом `1`; при успехе — `0`. Совпадающие входной и выходной пути запрещены.

Отчёт содержит количества и доли категорий, отдельно локальную ноду, смысл статусов и доступные метаданные запуска. Пустой массив `nodes` допустим и даёт нулевые показатели. Генератор не обращается к сети и не изменяет исходный JSON.
